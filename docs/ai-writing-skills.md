# 写作技能与页面交互

## SKILL.md 与 ai-prompts 的分工

| 层次 | 位置 | 职责 |
| --- | --- | --- |
| 聊天编排 | `ai/skills/<name>/SKILL.md` | 告诉聊天模型何时使用技能、如何传递用户要求、何时需要用户参与，以及如何处理结果。 |
| 单次生成 | `ai-prompts/*_{zh_CN,en_US}.md` | 告诉生成模型如何完成某项写作任务，包括内容规则、语言、输入模板和 JSON 输出格式。 |
| 执行与校验 | `AIWritingSkillService`、DTO、`AIWritingSkillCatalog` | 绑定处理器，解析并校验输入输出，限定哪些字段可应用。 |
| 页面交互 | 技能卡片与 `skillContract` | 根据已注册类型展示结果，检查草稿是否变化，接受用户选择或应用操作。 |

调用顺序是：聊天模型读取技能说明并调用工具 → 后端使用 `ai-prompts` 发起具体生成 → 解析、校验结果 → 返回页面卡片与模型可读结果。点击技能按钮时跳过聊天模型的工具选择，直接进入同一个生成与校验入口。

`SKILL.md` 不重复维护 JSON 示例、DTO 字段清单或可应用字段；这些内容有各自的生成模板和代码契约。修改标题风格等生成规则时改 `ai-prompts`，修改何时询问用户等工作步骤时改技能文档。Markdown 不能保证模型遵循规则，也不能代替后端校验。

当前借用了技能文档的组织方式，但实现是**内置白名单技能与工具绑定**：服务启动时读取文档，聊天请求一次性附带全部可用技能全文。没有按需读取技能文件、目录自动发现、执行 Markdown 中脚本或导入外部技能包的能力。模型也没有文件读取工具，在文档中添加相对链接不会自动加载其他资源。这里的 `name` 对应现有业务技能键（包括 `publishCheck`），不是外部技能包兼容声明。

`ai-prompts` 保留现有位置与语言回退逻辑，并供按钮、斜杠命令、聊天工具共用。具体资源映射见该目录的 [README](../zrlog-admin-ai/src/main/resources/ai-prompts/README.md)。生成模型不会收到编排用的 `SKILL.md`，避免把“请求用户选择”等步骤混入必须返回 JSON 的调用。

## 交互按用户任务决定

- “给这篇文章起几个标题”：生成标题卡片即可完成，不强制进入等待选择状态。
- “写一段列表页摘要”：直接生成摘要，不依赖标题技能。
- “先给我几个标题，我选好再写摘要”：生成标题后请求选择，收到答案再生成摘要。
- “推荐一个标题，再写摘要”：模型可以推荐候选中的一个并传递给摘要技能，无需再让用户选择。推荐不代表已应用标题。

未指定语气、配色等可选偏好时，使用文章上下文与生成模板的默认要求。只有缺少完成任务必需的信息或需要用户决定后续方向时才请求输入。任务中没有要求的改写、保存和发布不应由示例工作流自动引入。

## 契约与边界

- 内置技能在 `zrlog-admin-ai/src/main/resources/ai/skills/<name>/SKILL.md` 描述用途、工作步骤及交互条件。目录与可执行处理器由后端白名单绑定；Markdown 不允许注册任意代码或页面组件。
- 模型看到 `writing_<name>` 工具及技能说明，只能传入写作要求。正文来自本轮编辑器快照；生成调用复用 `AIWritingSkillService` / `AIToolService`，后端验证结果后才发送 `skill-result`。
- Markdown 指导聊天模型选择和编排技能；具体生成调用继续使用已有的任务提示词和结构化 DTO，避免把编排指令误当成文章或图片内容。
- 可应用结果附带版本化契约和编辑器快照标识，页面仅按已注册的技能类型渲染现有组件。自然语言回答不转换成可应用卡片。生成、选择、应用到本地编辑器、保存/发布是不同动作。
- `request_writing_input` 请求补充文字，或引用本轮标题结果让用户选择。候选项来自已验证的结果。后端持久化 `awaiting_input` 状态，结束当前 SSE；用户提交后以原始 tool call ID 恢复。拒绝、过期、重复提交、权限变化及草稿变化均需校验。
- 写作技能不依赖知识库开关；文章读写仍受原有工具权限与审批约束。`SKILL.md` 不改变权限策略。

## 实现切片

1. Markdown 技能目录、后端输入/输出验证与共享执行入口；保留按钮及斜杠命令兼容性。
2. 聊天工具分派、编辑器快照、技能结果 SSE 与会话持久化；页面复用现有卡片。
3. 输入交互暂停/恢复、选择卡片、草稿变化防护；以用户明确要求“标题生成 → 用户选择 → 摘要生成”验证暂停和恢复，此流程不是所有写作任务的固定顺序。
4. 后端/前端回归、Native 注册、工程护栏与页面构建。

## 内部协议

聊天请求可带 `editorContext` 与 `contextRevision`。前者为文章字段快照，后者为前端根据字段内容计算的稳定标识；它只用于检测本地内容变化，不是授权凭据。无快照的旧客户端仍可聊天和使用文章工具，但不提供写作工具。

`skill-result.messages` 返回后端生成的技能消息。消息中的 `skillContract` 包含 `version: 1`、`contextRevision` 和 `applicableFields`，实际 payload 仍沿用现有技能 DTO。会话完成事件可以包含用户消息、多条技能消息和最终回答。

新增内部 `POST /api/admin/article/ai/input` 接收 `articleId`、`runId`、`interactionId`、`decision`（submit/cancel）、`value` 和 `contextRevision`，返回新的 SSE。用户答案也保存为会话消息，标题卡片恢复已选项；同批中排在提问之后的工具调用返回未执行结果，由模型根据真实答案重新规划。`GET /api/admin/article/ai/run` 同时恢复等待输入的状态及已生成卡片。此接口属于 UI 内部协议，不纳入稳定 OpenAPI。

等待标题选择时只显示交互卡片，完成后恢复普通标题结果卡片。可应用结果只对生成时的编辑器内容有效；文章内容发生变化后需要重新生成。此限制也适用于先应用一张卡片再尝试应用另一张卡片，首期不提供批量应用。

## 验证重点

真实工具分派和结果校验；技能在知识库关闭时可用；无草稿不暴露技能；暂停后新实例恢复；相同调用不重复生成；选项篡改/重复提交/权限变化/过期/草稿变化；SSE 重放及刷新恢复；结果与普通回答明确分离；旧审批流程及手动技能兼容。

## 扩展技能

1. 在 `AIWritingSkillCatalog.KEYS` 注册键，并添加对应 `SKILL.md`。资源随白名单自动进入 Native 注册。
2. 在共享执行器中绑定具体生成服务，同时补充 `validateResult` 和 `applicableFields`；描述文件本身不能授予可应用字段或写权限。需要新生成模板时，在 `ai-prompts` 添加中英文资源并注册到 `AIPromptVO`，不要把编排指令注入生成提示词。
3. 使用已有结果类型时复用卡片；新结果类型需要同步增加 DTO、前端类型与渲染器。需要用户输入的步骤使用独立交互工具；需要保存或发布的步骤继续使用文章写工具及原有审批。

后端回归入口为 `AIWritingToolsTest`、`AIWritingSkillServiceTest` 和 `AIApprovalTest`；前端为 `article-ai-input.test.tsx`、`use-article-chat.test.tsx` 及助手组件测试。页面验证使用本地模拟供应商，实际经过生成服务、SSE、持久化与页面交互，不依赖外部供应商或付费请求。模拟供应商预设工具调用顺序，只验证执行与交互链路，不能证明真实模型会正确选用技能或判断何时提问；后者需要另行使用真实供应商评估。
