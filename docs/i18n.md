# i18n 规则

本工程的后台管理界面文案由前端维护，后端 i18n 只保留后端自己需要输出的消息。

## 后端

- 后端管理资源接口只返回运行时配置，例如 `lang`、主题、静态化开关、版本信息等。
- 后端代码如果需要翻译服务端消息，使用 `src/main/resources/i18n/admin_backend_*.properties`。
- 不要把前端界面文案重新加回后端 `admin_*.properties`。

## 前端

- 前端后台界面文案统一放在 `src/main/frontend/src/i18n/admin.ts`。
- 修改文案时必须同时维护 `zhCN` 和 `enUS`。`enUS` 需要满足 `AdminI18nResource`，缺少 key 应该由 TypeScript 检查发现。
- key 默认按实际路由前缀归类，不要优先按旧业务对象或泛化功能名归类。
- 页面里调用的文案，优先放到对应页面前缀下，例如 `/article-edit` 使用 `articleEdit.actions.save`、`articleEdit.saving`，`/comment` 使用 `comment.content`，`/website/admin` 使用 `websiteAdmin.theme.label`。
- 只有真正跨页面复用、且语义稳定的文案才放到顶层公共分组，例如 `common`、`error`、`fullscreen`。
- 不要因为文案“看起来通用”就先放顶层；如果当前只在单一路由页面使用，先归到该路由前缀下，后续真的复用时再上提。
- 对首页这类聚合页，显示在首页的文案仍归首页前缀，例如首页欢迎卡片里的“当前版本”应放在 `index.welcome.currentVersion`，而不是复用 `system.*`。
- 不要为了兼容旧的扁平 key 创建 alias map。应该直接把结构整理好。
- 前端 i18n 代码不要使用 `.properties`、`fs` 或运行时文件解析。浏览器包必须使用 TypeScript 模块。
- 组件、弹窗、消息提示、tooltip、表单 label、placeholder、empty state、按钮文字等可见 UI 文案不要硬编码。
- 不要保留 `getRes().x || "保存"` 这类 fallback 字面量。i18n key 缺失时应该让 TypeScript 检查失败。
- 不要使用字符串下标访问 i18n，例如 `getRes()["articleEdit.actions.save"]` 或 `res["title"]`。使用带类型检查的属性访问，例如 `getRes().articleEdit.actions.save`。
- 删除或替换 UI 文案时，同步移除不再使用的 i18n key。

## 检查

i18n 相关改动提交前至少执行：

```shell
cd src/main/frontend
yarn type-check
```

常用扫描命令：

```shell
rg -n 'getRes\(\)\[|\bres\[|adminI18nAliases' src/main/frontend/src --glob '*.ts' --glob '*.tsx'
rg -n '[\u4e00-\u9fff]' src/main/frontend/src --glob '*.ts' --glob '*.tsx' --glob '!src/main/frontend/src/i18n/**'
```

中文扫描会包含注释、SVG id、搜索关键字等非展示内容。处理结果时只迁移可见 UI 文案。
