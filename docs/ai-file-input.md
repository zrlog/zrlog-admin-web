# AI 助手文件输入

## 契约与范围

文章助手的 `POST /api/admin/article/ai` 接受可选 `files: [{name, data}]`；data 为标准 Base64 原始文件字节。仅已有账号与文章授权通过后保存文件，客户端不能指定服务器路径、远程 URL 或历史文件 ID。纯文本请求保持兼容。本接口属于后台 UI 内部协议。

OpenAI 的受支持模型通过 Responses 的 `input_file` 接收 PDF、Word（`.doc` / `.docx`）、PowerPoint（`.ppt` / `.pptx`）、Excel（`.xlsx` / `.xls`）、CSV / TSV 和 UTF-8 文本/代码。其他供应商的现有 Chat Completions 适配器暂不宣告文件输入；不支持的格式在请求模型之前拒绝。此功能是对话中的文档附件，不接入图片附件，也不改变已有封面生成功能。文件不会转换为博客公开附件或只作为 URL 拼进提示词。

Word / PowerPoint 按供应商的文本抽取流程读取，内嵌图片和图表不进入上下文；需要保留这些信息时应先转换为 PDF。

表格由 OpenAI 进行原生表格解析：每张工作表最多读取前 1,000 行，并生成摘要及表头元数据；不包含内嵌图片/图表，不承诺完整工作簿计算。界面选择表格后显示该限制。Office 文件按 ZIP / OLE 容器签名初检，最终内容解析由供应商执行；不在服务器执行宏或公式。

前后端统一使用编辑器初始化数据中的 `aiFileInput`，其中声明扩展名、最多 4 个文件、单文件 4 MiB、单次合计 8 MiB。后端重新验证名称、文件头签名、Base64 和大小。聊天 HTTP 请求上限 12 MiB；沿用部署层的请求体限制。

文件私有存储于运行目录的 `conf/ai-input-files/<账号 ID>`，随机 ID 与原始文件名分离。会话、执行检查点、导出及浏览器只保留文件元数据；向供应商发请求时按当前账号读取字节。文件可用于后续追问和工具确认后的续接；模型配置变化时重新验证兼容性。上下文仍受现有历史窗口限制，文件上下文额外限制为 16 MiB。原始文件保留 30 天，每个账号最多 128 MiB；过期文件在下次保存时清理，历史引用失效时明确报错并要求重新添加。清空对话时清理该会话及检查点的文件；仍被其他会话（例如草稿迁移）引用的文件保留。文章删除及中断请求遗留的文件通过到期清理回收。

## 验证

覆盖原始文件到供应商请求的字节一致性、模型/格式不匹配、伪造格式、大小限制、账号隔离、路径穿越、历史追问与确认续接，验证普通文本/工具调用协议不变。前端覆盖选择、移除、失败保留、排队和文件随请求发送，并运行类型检查、生产构建及 Native DTO 护栏。

协议来源：[OpenAI 文件输入](https://developers.openai.com/api/docs/guides/file-inputs)。

本次本地验证：88 项后端相关测试、63 项前端相关测试通过；TypeScript 类型检查、生产构建、Native JSON 注册及工程护栏通过。独立界面预览验证桌面、手机和手机深色模式的文件选择、移除及发送，未发现横向溢出或浏览器错误。供应商协议通过模拟 HTTP 客户端检查原始 PDF / CSV / XLSX 字节、MIME 和历史续接；没有调用真实模型推理。后端测试使用 `/tmp/zrlog-agent-audit-20261012/m2` 中已包含 agent 审计 getter 修复的 base 快照，未修改本次任务之外的 base 源码。
