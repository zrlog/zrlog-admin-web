# AI 助手文件输入

## 契约与范围

文章助手的 `POST /api/admin/article/ai` 接受可选 `files: [{name, data}]`；data 为标准 Base64 原始文件字节。仅已有账号与文章授权通过后保存文件，客户端不能指定服务器路径、远程 URL 或历史文件 ID。纯文本请求保持兼容。本接口属于后台 UI 内部协议。

OpenAI 的受支持模型通过 Responses 的 `input_file` 接收 PDF、Word（`.doc` / `.docx`）、PowerPoint（`.ppt` / `.pptx`）、Excel（`.xlsx` / `.xls`）、CSV / TSV 和 UTF-8 文本/代码。PNG、JPEG（`.jpg` / `.jpeg`）和 WebP 使用 `input_image`，图片原始字节通过 `image_url` 的 Base64 data URL 发送，`detail` 为 `auto`；同一消息可以混合图片和文档。其他供应商的现有 Chat Completions 适配器暂不宣告附件输入；不支持的格式在请求模型之前拒绝。图片附件用于理解已有图片，不改变已有封面生成功能。文件不会转换为博客公开附件或只作为 URL 拼进提示词。

本次兼容原有 `files: [{name, data}]` 请求、附件元数据和私有存储，不新增公开下载接口或依赖。图片按扩展名匹配 PNG / JPEG / WebP 文件头，JPEG 检查结束标记、WebP 检查 RIFF 长度；最终解码由供应商完成。SVG、GIF、HEIC 等未开放格式会明确拒绝。现有 `OpenAIResponses.Content` 新增 `image_url`、`detail`，沿用该类型的 Native/Gson 注册。

Word / PowerPoint 按供应商的文本抽取流程读取，内嵌图片和图表不进入上下文；需要保留这些信息时应先转换为 PDF。

表格由 OpenAI 进行原生表格解析：每张工作表最多读取前 1,000 行，并生成摘要及表头元数据；不包含内嵌图片/图表，不承诺完整工作簿计算。界面选择表格后显示该限制。Office 文件按 ZIP / OLE 容器签名初检，最终内容解析由供应商执行；不在服务器执行宏或公式。

前后端统一使用编辑器初始化数据中的 `aiFileInput`，其中声明扩展名、最多 4 个文件、单文件 4 MiB、单次合计 8 MiB。后端重新验证名称、文件头签名、Base64 和大小。聊天 HTTP 请求上限 12 MiB；沿用部署层的请求体限制。

文件私有存储于运行目录的 `conf/ai-input-files/<账号 ID>`，随机 ID 与原始文件名分离。会话、执行检查点、导出及浏览器只保留文件元数据；向供应商发请求时按当前账号读取字节。文件可用于后续追问和工具确认后的续接；模型配置变化时重新验证兼容性。上下文仍受现有历史窗口限制，文件上下文额外限制为 16 MiB。原始文件保留 30 天，每个账号最多 128 MiB；过期文件在下次保存时清理，历史引用失效时明确报错并要求重新添加。清空对话时清理该会话及检查点的文件；仍被其他会话（例如草稿迁移）引用的文件保留。文章删除及中断请求遗留的文件通过到期清理回收。

## 图片预览接口

后台 UI 内部 `GET /api/admin/article/ai/file?id=<文章 ID，草稿为 0>&fileId=<附件 UUID>` 返回 PNG / JPEG / WebP 原始字节。沿用后台登录、`article.assist` 及文章访问校验；只能读取当前账号、当前文章会话或执行检查点中引用的图片。文件名、MIME、大小、到期时间取自服务端记录，不接受客户端路径。读取复用账号目录隔离、文件大小/到期/符号链接校验，返回正确图片 MIME、`Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`。图片不放进公开资源目录，已有导出仍仅含元数据。前端复用带 context path 的 Axios 实例读取 Blob，创建临时 object URL；请求取消、切换文章或组件卸载时清理。读取失败保留文件信息并提供重新加载入口。

## 附件交互

输入区采用统一圆角容器：附件卡片、自动增高的文本区和底部操作栏置于同一框内；左侧「＋」展开本地附件与资源库入口，技能入口在旁，发送/停止按钮置于右侧。输入区支持选择、拖入文件及粘贴截图。普通文本粘贴保持原行为；剪贴板同时包含文字和图片时保留文字输入并添加图片。三种入口共用格式、数量和大小校验，失败时保留已选附件。附件卡片显示名称、大小和类型，已选及排队中的本地图片提供缩略图和放大预览，移除或组件卸载时释放 object URL。已发送图片继续显示缩略图并可放大。发送期间的本地 File 仅以 WeakMap 关联消息元数据，不进入消息 JSON、导出或浏览器持久缓存；刷新后通过鉴权接口恢复预览。文件名保持单行省略，可悬停、聚焦或点按查看完整名称。

资源模块启用且账号有 `file.manage` 权限时，「＋」菜单提供“从资源库选择”。选择器复用已有资源目录、搜索和网格/列表，按当前模型支持的图片扩展名筛选，支持点击及键盘选择。选中图片读取完成后加入同一附件列表，可预览、移除和随消息发送；数量与剩余总大小沿用当前消息限制。读取期间防止重复选择，关闭弹窗会中止请求，迟到的结果不会重新添加附件。失败提示留在弹窗内，可以重新选择；关闭后焦点返回附件入口。

本站图片使用资源库原始 `/attached/…` 路径，通过已有鉴权下载接口读取；展示 URL 中的 backend server / context path 不会再次拼入原始路径。外链图片由浏览器读取，省略凭据及后台请求头，需图片源允许 CORS；无法读取时可下载后通过本地附件入口添加。通过 PNG / JPEG / WebP 文件头校验读取内容，兼容下载接口把图片误标为 JSON 的现有响应，并拒绝真正的 JSON / HTML 错误页。下载前检查已知大小，下载期间和完成后继续限制字节数；不新增服务器远程抓取接口。资源库选择只把读取到的原始图片字节交给现有附件请求，不将图片 URL 直接发送给模型。

数量、大小和格式限制收进「＋」菜单内的“格式与大小限制”，按需展开；输入区不常驻附件操作和会话说明。读取附件时显示实际读取状态，发送中的状态沿用现有对话请求反馈；不显示虚构上传百分比。发送失败或抛出异常时，原始 File 留在暂停的发送队列，用户可以重试或移除。
