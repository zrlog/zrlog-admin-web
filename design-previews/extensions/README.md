# 扩展管理设计预览

状态：布局已获用户确认。正式页面使用所在工程的 Ant Design 组件、主题 token 和文案规范；此目录仅保存设计预览，不接入正式路由、构建或后台接口。

- `themes.html`：主题管理，默认网格。
- `plugins.html`：插件管理，默认列表。

两份预览均可切换主题／插件页面、搜索、筛选、切换列表／网格和明暗外观。
主题应用只更新预览内存中的示例状态；配置、上传、市场和运行时入口仅说明去向。
主题封面、版本、插件服务和安装数量均为示例，不代表当前站点的真实数据。

## 已确认的设计

- 页头统一为名称、安装数量、简短说明和右侧操作。
- 获取更多主题／插件统一放在右上角；主题保留上传，插件保留运行时控制台。
- 搜索、分类筛选和视图切换使用相同布局。
- 主题默认展示横向预览卡片，保留应用、预览、配置和删除的语义。
- 内置主题有独立的“内置”标签和“内置主题”筛选项，与“已应用／预览中”分别展示。内置主题在切换停用后仍不可删除。
- 主题作者名称带外链标识，在新标签页打开对应作者／团队主页；网格和列表都保留此入口，没有主页时仅显示作者文字。设计稿使用示例地址，正式实现采用主题元数据提供的主页地址。
- 插件默认使用列表，展示插件描述、服务、管理和卸载；系统插件不可卸载。
- 统一使用主题色、圆角、文字和边框 token，支持明暗模式及窄屏。

实现分别落在 `zrlog-admin-web` 和 `zrlog-plugin-core`，不跨仓库复制组件或合并业务。
主题配置继续使用原有 React Router Link；插件页面保持原有宿主和业务边界。
正式实现时复用工程主题 token 和 i18n，保留现有 API、数据归属及操作流程。

## 数据契约与实现切片

1. 后台主题列表增加 `builtIn`，依据 `BundledThemes` 的 SPI 注册表生成。它表示通过 SPI 发现的主题，与加载资源是否位于 classpath、文件扩展名、当前启用状态和 `deleteAble` 分开。原响应字段保留，同步注册 native/Gson DTO。
2. 主题页增加搜索、内置筛选、列表／网格切换和作者主页；上传、预览、应用、配置、删除沿用现有接口及缓存刷新流程。
3. 插件页采用相同页头和工具栏布局，保留插件自己的管理、卸载、服务信息及运行时控制台。系统插件继续由 `requiredPlugins` 标识。

主题列表属于后台 UI 内部接口，不新增到稳定 OpenAPI 清单。
不修改主题 SPI、插件运行时协议、页面路由、安装协议或构建发布流程。
